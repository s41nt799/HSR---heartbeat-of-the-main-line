## Архитектурные решения

**Frontend:**
- React 18 (StrictMode), TypeScript strict, Vite 6, TanStack Query 5, Zustand 5, Tailwind CSS 3, Axios 1.x
- Маршрутизация: react-router-dom 6
- Состояние: Auth — Zustand, серверное — TanStack Query, таймер — `useRef` + `useEffect` + `useState`
- Стилизация: Tailwind CSS + кастомные анимации (fade, pulseSoft, achievementIn)
- API: Axios с interceptors (401 → logout), отдельный `api/`-слой для всех запросов
- Точность: TypeScript strict, нет `any` в компонентах

**Backend:**
- FastAPI (async), SQLAlchemy 2.0, Alembic для миграций
- PostgreSQL 15 для хранения, Redis для лидерборда (ZSET)
- JWT: access + refresh токены
- Идемпотентность игровых действий через `version` сессии
- Модульная структура: `api/` → `services/` → `models/`
- Docker Compose для подъёма одной командой

**Контент:**
- Сценарии и ачивки — JSON-файлы в `content/`
- Загружаются сидом в БД, ядро не зависит от контента
- Новый сценарий добавляется без пересборки приложения

## Вклад в репозиторий

### Frontend

1. TypeScript strict, без `any`
2. Все запросы через `api/`-слой, не в компонентах
3. Loading / empty / error на всех экранах
4. Кнопки disabled при `isPending` или `state !== 'active'`
5. Минимальные CSS-transitions, без мультимедиа
6. Таймер — только отображение, решение о timeout на сервере
7. Каждый файл — осмысленное имя, компонент — PascalCase

### Backend

1. Async SQLAlchemy 2.0, никаких синхронных запросов в роутах
2. Миграции через Alembic, не через `create_all`
3. Валидация входных данных через Pydantic-схемы
4. Идемпотентность игровых действий: повторный `/choice` или `/finish` не дублирует события и ачивки
5. Единый формат ошибок (`{ detail: string | { msg }[] }`, FastAPI-стиль)
6. Секреты — только через `.env`, не в коде
7. Redis-fallback: если Redis недоступен, лидерборд отдаётся из Postgres

### Game-Design

1. Контент — только JSON, схема согласована с backend
2. Тексты узлов ≤ 220 символов, выборов ≤ 80
3. Эффекты в допустимых диапазонах: `loyalty`/`safety` −30…+25, `points` −30…+60
4. На каждом `critical`-узле — скрытый `timeout`-выбор с `is_visible: false`
5. Обязательны `ending_success` и `ending_fail` в каждом сценарии
6. Нет тупиков: из любого нетерминального узла есть путь к концовке
7. Баланс: оптимальный путь → шкалы ≥ 60, ошибки → резкое падение
8. `debrief_hints` для каждого критического узла
9. JSON валиден, проверен на jsonlint.com

## Правила работы с репозиторием

1. **Ветки:** `feature/<scope>`, `fix/<scope>`, `chore/<scope>`
2. **Коммиты:** краткие, по группам — `feat(auth): ...`, `fix(api): ...`, `chore(content): ...`
3. **Осмысленная история:** инкрементальные коммиты, не один дамп всего кода
4. **Ревью:** перед мержем в `main` — минимум один человек смотрит дифф
5. **Никаких секретов в репозитории:** `.env` в `.gitignore`, шаблон — `.env.example`
6. **Синтетические данные:** только вымышленные, соответствие 152-ФЗ
