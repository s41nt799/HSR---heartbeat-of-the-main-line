# LIMITATIONS.md — Ограничения решения

## Backend-зависимые функции

1. **Level в UserMe и Profile** — реализуется клиентским вычислением `computeLevel()`, ожидается серверное значение в будущем
2. **Scenarios loading** — пока реализовано через mock-фикстуры, backend должен предоставить эндпоинт `/api/v1/scenarios`
3. **Scenario ID в DebriefResponse** — кэшируется локально через sessionStorage, будет удален когда backend добавит поле
4. **Analytics компетенций** — `/profile/analytics` не реализован, зависит от backend
5. **Челленджи** — `/challenges` не реализован, зависит от backend
6. **Уведомления** — `/notifications` не реализован, зависит от backend
7. **Leaderboard scope** — фильтр по scope (company/depo/brigade) не реализован, доступен только global
8. **Swagger/OpenAPI** — спецификация пока не предоставлена backend-командой, будет интегрирована позже

## Известные ограничения фронтенда

1. **Таймер** — вычисление оставшегося времени происходит на клиенте на основе `deadline` и `server_now` от backend. При некорректных датах на сервере могут быть некорректные значения.
2. **О프лайн-режим** — при потере связи с сервером активная сессия сохраняется в localStorage, но новые действия недоступны до восстановления связи.
3. **Кэш сессий** — использование sessionStorage для rememberSessionScenario имеет ограничения в приватных режимах браузеров.
4. **Mock-данные** — при недоступности backend отображаются фейковые данные, поведение может отличаться от боевого.

## Bezопасность

1. **JWT хранится в localStorage** — XSS-уязвимости могут привести к краже токена. Внедрение httpOnly cookie рекомендуется для продакшена.
2. **Axios interceptor 401** — при получении 401 токен удаляется и пользователь редиректится на /login.
3. **Синтетические данные** — все данные (уровни, очки, ачивки) являются вымышленными для тренажера, соответствуют 152-ФЗ о защите персональных данных.
